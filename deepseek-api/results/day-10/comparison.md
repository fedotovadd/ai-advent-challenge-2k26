В основных вызовах сохранён режим thinking провайдера по умолчанию; отправлен параметр temperature=0, но в этом режиме он не действует. В служебных вызовах facts/summary thinking отключён, лимиты 1200/512 токенов. См. [документацию DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/). Вызовы и токены включают извлечение facts и обновление summary. Числа берутся из usage API (поле source в JSON); стоимость рассчитана по тарифам, уже заданным в приложении, без учёта cache hit. Время — сумма длительностей вызовов внутри стратегии, режимы запускались независимо, часть прогонов — параллельно.

Оценка — прозрачная проверка 12 полей JSON по ключевым признакам из исходного ТЗ. Для цели учитывается также предмет проекта из поля project; бюджет должен быть точным числом, дата включает месяц. Это проверка сохранения требований, а не независимая экспертная оценка качества текста. Ниже сохранены ответы и результаты каждого пункта. Один прогон не измеряет статистическую повторяемость.

Среди режимов с 12/12 полей в итоге дешевле: branching.
Facts требует дополнительного запроса после каждого user; Branching хранит полную историю. На более длинном диалоге соотношение расходов может измениться.

## Сценарий

1. Собираем ТЗ: проект «Листок», цель — запись на занятия в студии керамики.
2. Аудитория — взрослые новички. Бюджет на MVP 100000 рублей.
3. Дедлайн — 20 ноября 2026. Платформа — веб-сайт, удобный на телефоне.
4. Интерфейс только на русском. Регистрация по email, без социальных сетей.
5. Онлайн-оплаты в MVP не будет: платят в студии. Уведомления только по email, без SMS.
6. Нужен экспорт записей в CSV. Размещаем на собственном сервере студии.
7. Список занятий должен показывать дату и количество свободных мест.
8. Администратор может отменить занятие, письмо уходит всем записавшимся.
9. Изменение договорённости: бюджет теперь 200000 рублей вместо 100000. Всё остальное остаётся.
10. При заполнении группы запись закрывается. Лист ожидания пока не нужен.
11. Проверь все текущие договорённости. Верни только JSON с ключами project, goal, audience, budget, deadline, platform, language, registration, payments, notifications, export, hosting. budget — число рублей. Остальные значения — короткие строки. Если данных нет в доступном контексте, используй null. Не додумывай.
12. В форме записи достаточно имени и email. Телефон не собираем.
13. Добавь экран «Мои записи» и возможность отменить свою запись.
14. Критерий приёмки: нельзя записать больше людей, чем вместимость группы.
15. Составь итоговое ТЗ. Проверь все текущие договорённости. Верни только JSON с ключами project, goal, audience, budget, deadline, platform, language, registration, payments, notifications, export, hosting. budget — число рублей. ## Удобство и ограничения

| Режим | Удобство | Ограничения |
|---|---|---|
| Sliding Window | Один параметр N; минимальное управление | Старые детали исчезают, приходится повторять; увеличение N не восстанавливает их |
| Facts | Видимый словарь сохраняет явные договорённости | Дополнительный вызов на каждый user; ошибки извлечения и ограничение 32 факта |
| Branching | Можно проверить альтернативы и вернуться к исходному ТЗ | Нужно явно создавать checkpoint; полная история каждой ветки увеличивает вход |
| Summary | Длинный диалог продолжается с пакетным сжатием | Сводка может потерять точность; её обновление стоит токены |

Системные тесты отдельно проверяют физическое удаление, исправление/удаление facts, неизменяемость checkpoint, отсутствие соседних веток в payload и восстановление с диска.
