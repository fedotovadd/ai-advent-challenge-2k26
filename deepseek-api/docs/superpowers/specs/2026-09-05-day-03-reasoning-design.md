# День 3: сравнение способов рассуждения — Design Spec

## Цель

Дополнить локальный веб-чат отдельным экспериментом для задания третьего дня. Эксперимент решает одну и ту же логическую задачу через API четырьмя способами и показывает полученные решения рядом с единым эталоном, чтобы пользователь мог сравнить ответы и определить наиболее точный способ.

## Задача и эталон

Во всех запросах используется неизменный текст задачи:

> За закрытой дверью находится лампочка. Снаружи — три выключателя, и только один из них подключён к лампочке. В комнату можно войти только один раз. Как определить, какой выключатель подключён к лампочке?

Эталонное решение, отображаемое в интерфейсе и документации: включить первый выключатель на несколько минут, выключить его, включить второй и войти в комнату. Горящая лампа соответствует второму выключателю; выключенная, но тёплая — первому; выключенная и холодная — третьему.

## Варианты эксперимента

Кнопка «Запустить эксперимент» выполняет четыре независимых варианта. Для сопоставимости они не используют историю активной сессии и пользовательские настройки чата; каждому передаётся базовый системный промпт приложения и новый пользовательский запрос.

1. **Прямой ответ.** В API передаётся только текст задачи.
2. **Пошаговое решение.** К тексту задачи добавляется инструкция «Решай пошагово».
3. **Сначала создать промпт.** Первый API-вызов просит модель сформулировать лучший промпт для решения именно этой задачи. Его текст сохраняется в результате. Второй API-вызов использует этот сгенерированный промпт как пользовательское сообщение и возвращает решение. Это один метод эксперимента, хотя для его выполнения требуются два вызова API.
4. **Группа экспертов.** Один API-вызов задаёт роли аналитика, инженера и критика. Он требует отдельное решение от каждой роли и краткий общий вывод.

Промпты должны быть явными на русском языке и содержать сам текст задачи там, где он нужен. Третий вариант не должен подменяться заранее заготовленным шаблоном: второй его вызов обязан использовать фактически возвращённый моделью промпт.

## Серверный контракт

Добавляется защищённый проверкой same-origin маршрут `POST /api/day-03/run`. Запрос не принимает пользовательских параметров. Ответ при успехе имеет один объект `experiment` с:

- текстом задачи и эталонным решением;
- четырьмя результатами в фиксированном порядке: идентификатор метода, русское название, исходный промпт и ответ модели;
- для третьего метода — отдельно сохранённым промптом, составленным моделью.

Вызовы модели выполняются последовательно через уже внедряемую функцию `ask_model`; это оставляет тесты полностью локальными. При отсутствии ключа, пустом ответе либо ошибке провайдера маршрут возвращает понятную ошибку API в том же стиле, что и существующий маршрут отправки сообщения. Частично собранный эксперимент не сохраняется и не выдаётся как окончательный результат.

## Интерфейс

В центральной части страницы появляется самостоятельная тёмная лаборатория «День 3 — способы рассуждения», визуально отделённая от обычного чата. Её верхняя панель содержит название, неизменяемый текст выбранной задачи, кнопку «Запустить 4 стратегии» и строку состояния. Во время работы кнопка недоступна.

Под верхней панелью всегда находятся четыре равноправные карточки в сетке 2×2 на широком экране и в одну колонку на узком. Карточки идут в порядке эксперимента: «Напрямую», «Пошагово», «Свой промпт», «Группа экспертов». До запуска каждая объясняет метод и сообщает, что результат ещё не получен. После успешного ответа каждая карточка выводит:

- короткое описание метода и результат модели;
- раскрываемую область «Что будет отправлено в модель» с отдельными визуальными блоками `system` и `user`, чтобы промпты четырёх стратегий можно было сравнить рядом;
- в карточке «Свой промпт» — дополнительно промпт, который составила модель, и пометку о двух вызовах API;
- в карточке экспертов — полный ответ, чтобы решения аналитика, инженера и критика не были сокращены клиентом.

Эталонное решение и критерии сравнения выводятся отдельной нижней панелью лаборатории после получения всех четырёх результатов.

Блок не добавляет результаты в историю обычного чата, не изменяет текущую сессию и безопасно вставляет текст через `textContent`. При ошибке он показывает сообщение, не затирая последний успешный результат.

## Сравнение результатов

Приложение не будет выдавать недостоверную автоматическую оценку качества на основе поиска отдельных слов. Вместо этого внизу эксперимента будет постоянная, проверяемая шкала сравнения с тремя критериями точного ответа: правильная последовательность действий, использование нагрева лампы и корректное сопоставление всех трёх состояний выключателям. Пользователь видит эталон и каждый полный ответ рядом, поэтому может прозрачно определить, отличаются ли ответы и какой из них покрывает все критерии. README содержит эту же шкалу и инструкцию зафиксировать вывод по реальному запуску API.

## Тестирование

Расширить текущие `unittest`-тесты HTTP-сервера и контрактов страницы:

- страница содержит блок эксперимента, кнопку и клиентскую логику вызова нового маршрута;
- маршрут возвращает результаты в нужном порядке при подставной модели;
- проверяется точное содержание промптов для прямого, пошагового и экспертного вариантов;
- проверяется, что второй вызов третьего метода получает именно текст промпта, который вернула подставная модель;
- ошибка модели, пустой ответ, запрос с другого источника и неподдерживаемое тело запроса возвращают ожидаемые ошибки и не создают частичный результат;
- существующие тесты сессий, настроек и чата остаются зелёными.

## Документация

README описывает новый блок, четыре метода, особенность двух API-вызовов для третьего метода, эталон и критерии ручного сравнения. Инструкция сохраняет действующий способ задания `DEEPSEEK_API_KEY` и запуска приложения.

## Границы

В работу не входят: изменение модели, хранение результатов между перезапусками, произвольный редактор задачи, автоматическое ранжирование ответов моделью или изменение существующих настроек/истории чата. Эти функции не требуются для задания и сделали бы сравнение менее воспроизводимым.
