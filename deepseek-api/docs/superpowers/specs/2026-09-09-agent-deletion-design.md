# Удаление агента

## Цель

Пользователь может безвозвратно удалить любого агента вместе с его историей
переписки, настройками и метаданными последнего запроса.

## Интерфейс

В карточке выбранного агента в левой панели отображается кнопка-крестик с
понятной подписью для программ чтения с экрана. Нажатие показывает нативное
подтверждение с именем агента и предупреждением о безвозвратном удалении.
Отмена не меняет состояние.

После подтверждения карточка исчезает. Если остаются агенты, активным
становится соседний: следующий в списке, либо предыдущий, если удалённый был
последним. Если агентов не осталось, чат, настройки и метаданные переходят в
пустое состояние; отправка сообщения недоступна. Пустой список сохраняется
между перезапусками; создание нового агента продолжает счётчик идентификаторов,
а не возрождает удалённого `agent-1`.

Клиент также очищает связанные только с удалённым агентом локальные черновики,
индикатор ожидания, сообщение об ошибке и отложенное сохранение настроек.
Перед удалением он дожидается завершения сохранения настроек. Ответы уже
запущенных запросов сообщений или настроек для удалённого идентификатора
игнорируются, поэтому удалённая карточка не может появиться вновь.

## Сервер и хранение

Добавляется маршрут `DELETE /api/agents/{id}`. Он проверяет origin, удаляет
агента через реестр и атомарно сохраняет новое состояние. Изменение становится
видимым в памяти только после успешной записи: при ошибке сохранения реестр и
последующий `GET` сохраняют исходного агента. Успех возвращает `200` и
идентификатор удалённого агента. Для несуществующего идентификатора
возвращается `404`; ошибка сохранения возвращает существующий безопасный ответ
`500`.

В реестре удаляется объект агента из единственного источника данных. Поэтому
его сообщения, настройки и метаданные не попадают в следующую запись
`data/agents.json`; последовательность выдачи новых идентификаторов не
изменяется. Загрузчик признаёт корректным пустой список, если `nextId` —
положительное число. Операции реестра сериализуются: запрос сообщения или
настроек, проигравший удалению, возвращает `404`; удаление ждёт уже начатого
ответа модели и затем удаляет его окончательное состояние.

## Проверка

Тесты покрывают удаление из реестра и записанного JSON, ответ API при успехе,
`404` для отсутствующего агента, пустое сохранённое состояние после перезапуска
и сохранение остальных агентов. Отдельно проверяются откат при ошибке записи,
проверка same-origin для `DELETE` и безопасный результат гонки с сообщением или
настройками. Тест интерфейса проверяет наличие кнопки-крестика, подтверждения,
обновление активного выбора, очистку локального состояния и игнорирование
запоздалого ответа удалённого агента. Логику выбора и очистки выделяют в
небольшие чистые функции, чтобы её можно было проверить без браузера.
