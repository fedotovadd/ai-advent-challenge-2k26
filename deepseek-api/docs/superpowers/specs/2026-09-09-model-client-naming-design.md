# Нейтральное имя адаптера модели

## Контекст

`providers.ask_deepseek` выбирает не только DeepSeek: для модели `glm-4.7-flash` он использует API Z.AI. Имя отражает раннюю историю проекта, но больше не отражает фактическую ответственность функции.

## Решение

Переименовать публичную функцию из `ask_deepseek` в `ask_model`.

`Agent`, `AgentRegistry`, `ChatServer` и эксперимент Дня 3 уже получают вызываемую функцию как зависимость с нейтральным именем `ask_model`; их API и поведение не меняются. Новый импорт в `main.py` также использует `ask_model` как значение по умолчанию для `create_server`.

## Почему не класс

Операция не хранит состояние и делает один вызов к одному из двух совместимых API. Класс не добавил бы самостоятельной ответственности или вариативности. Если позже появятся retries, таймауты, fallback, отдельные клиенты с несовместимыми протоколами или telemetry, функцию можно развить в объект `ModelClient` без изменения `Agent`: ему по-прежнему можно передавать вызываемый метод `client.ask_model`.

## Проверка

Сначала тест провайдера должен импортировать и вызвать `providers.ask_model`; до переименования он обязан завершиться ошибкой импорта/отсутствующего атрибута. После переименования тест проверяет выбор Z.AI для GLM, передачу ключа и возврат содержимого ответа. Затем запускается весь набор тестов.
