# День 7 — сохранение контекста агента

## Цель

После остановки и следующего запуска приложения каждый агент продолжает
диалог с прежней историей и настройками. Следующий вызов модели получает
сообщения, накопленные до перезапуска, как если бы сервер не выключался.

## Решение

Приложение хранит состояние реестра агентов в JSON-файле
`deepseek-api/data/agents.json`. В файле сохраняются снимки всех агентов и
следующий номер для их идентификаторов. Снимок агента уже содержит его
`messages`, `settings` и `metadata`, поэтому восстановление возвращает
контекст и конфигурацию каждого агента целиком. Путь передаётся в реестр как
зависимость, чтобы тесты использовали отдельный временный файл.

JSON выбран вместо SQLite: для небольшого локального учебного приложения он
не требует дополнительной зависимости и остаётся удобным для проверки.

## Поток данных

1. При создании `AgentRegistry` хранилище пытается прочитать JSON-файл.
2. Корректное состояние имеет версию `1`, непустой список агентов и `nextId`,
   который больше номера каждого идентификатора вида `agent-N` в этом списке.
   У каждого агента проверяются строковые `id` и `name`, список сообщений с
   ролями `user` или `assistant` и непустым текстом, полный набор валидных
   настроек и `metadata`: `null` либо объект с ожидаемыми ключами последнего
   вызова. Если эта проверка не проходит, файл не загружается и реестр начинает
   работу с обычным «Агентом 1».
3. Реестр сохраняет новое состояние после создания агента, изменения его
   настроек и любой попытки ответа: пользовательское сообщение не потеряется
   даже при ошибке API; успешный ответ также сохраняется.
4. Запись выполняется атомарной заменой временного файла, чтобы не оставить
   частично записанный JSON при остановке процесса.

## Границы и ошибки

Хранилище не записывает API-ключи: их в снимках агентов нет. Некорректный,
неполный или повреждённый файл не должен мешать запуску сервера. В этом случае
он не загружается, а приложение начинает новый реестр по умолчанию.

Ошибка записи не замалчивается. Если изменения нельзя сохранить, операция
возвращает отдельную ошибку сохранения, а HTTP-слой отвечает `500` с понятным
сообщением. При этом данные остаются в памяти текущего процесса, но клиент не
получает ложного подтверждения, что контекст переживёт перезапуск.

## Проверка

Автоматические тесты проверят сохранение сообщений и настроек, восстановление
после создания нового реестра и использование восстановленной истории в
следующем payload модели. Отдельные тесты подтвердят безопасный старт при
повреждённом файле и понятную ошибку при невозможности записать файл. В
руководстве запуска будет описан ручной сценарий:
отправить сообщение, перезапустить приложение и продолжить разговор.
