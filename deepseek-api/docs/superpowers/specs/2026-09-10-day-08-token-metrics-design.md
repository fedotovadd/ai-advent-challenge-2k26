# Метрики токенов и контекстного окна — дизайн

## Цель

Добавить каждому агенту изолированные метрики токенов и стоимости, чтобы в интерфейсе было видно рост полного payload при продолжении диалога и поведение при переполнении контекстного окна.

## Границы и данные

`Agent` остаётся единственным владельцем истории, настроек, формирования payload и метрик. Для каждой модели конфигурация включает реальный лимит контекста, тарифы в USD за 1 млн токенов, максимум ответа и безопасное значение ответа по умолчанию. Для `deepseek-v4-flash` и `deepseek-v4-pro` это 1 млн контекста и 384 тыс. максимального ответа; для `glm-4.7-flash` — 200 тыс. и 128 тыс. соответственно. Безопасное значение без заданного `maxTokens` — 4096. В настройках агента появятся учебный лимит контекста (необязательное переопределение) и флаг демонстрационного запроса при переполнении.

Перед каждым вызовом агент локально оценивает токены: нового сообщения, истории до него, полного payload с системной инструкцией и служебной структурой. Оценки помечаются как приблизительные. После получения текстового ответа тот же оценщик вычисляет его размер; при fallback `estimatedTotalTokens = estimatedPromptTokens + estimatedCompletionTokens`. Успешный ответ API дополняет запись фактическими `prompt_tokens`, `completion_tokens` и `total_tokens`; эти значения используются для итогов и стоимости. Если usage отсутствует или неполон, запись сохраняет эти три локальные оценки с признаком «Оценка»; стоимость также остаётся оценочной, а не фактической. Для бесплатной модели стоимость хранится числом 0 с признаком `free` и показывается как «Бесплатно».

Каждый успешный вызов создаёт отдельную запись истории расходов. В ней остаются номера сообщений, входные и выходные токены, сумма шага, накопленные токены, стоимость и оценочные размеры истории. Для платных моделей цена шага равна `(input * inputUsdPerMillion + output * outputUsdPerMillion) / 1_000_000`; значение хранится в USD без потери точности в данных и округляется только при отображении. Накопленные показатели выводятся из этой истории, поэтому не смешиваются между агентами. Последняя отклонённая проверка контекста хранится отдельно как `lastContextAttempt` (оценка входа, резерв ответа, активный лимит и причина) и никогда не меняет накопленные токены или стоимость.

## Контекстное окно и демонстрация ошибки провайдера

Реальный лимит модели всегда остаётся в конфигурации. Для учебной демонстрации `trainingContextLimit`, если задан, используется только как активный лимит локальной проверки и индикатора; иначе активен реальный лимит. Процент контекста — `оценка входа / активный лимит`; он не включает резерв ответа, чтобы соответствовать полю «Использовано контекста». Проверка отправки использует `оценка входа + requestedOutputLimit <= активный лимит`, где `requestedOutputLimit` равен `settings.maxTokens`, а при его отсутствии — безопасному максимуму из конфигурации модели. При 80–99% интерфейс показывает предупреждение.

По умолчанию переполнение блокирует вызов до API: пользовательское сообщение и история модели не меняются, а метрики фиксируют отказ и его причину. В правой панели доступен флажок «Отправлять запрос при переполнении — для демонстрации».

Если флажок включён, агент строит временный payload и отправляет его провайдеру, но не добавляет новое сообщение в сохранённую историю заранее. Если провайдер вернул ошибку, сервер передаёт в браузер исходный текст из `error.message`, затем из верхнеуровневого `message`; если их нет, выводит HTTP-статус и маскированное тело ответа. Текст не перефразируется, маскируются только потенциальные секреты; чат выводит его отдельной ошибочной репликой. Эта реплика и пробное сообщение не становятся частью будущего контекста. При сетевой, API- или ошибке разбора ничего из пробной пары не сохраняется. Если провайдер принял запрос и вернул корректный ответ, агент одной операцией добавляет пользовательское сообщение и ответ как обычную успешную пару и включает их в метрики.

## Интерфейс

Правая панель выбранного агента получает секцию «Токены и стоимость»: сводку сессии, параметры последнего сообщения, индикатор использования контекста, предупреждение/детали отказа, флажок демонстрационного запроса, таблицу расходов и SVG-график входных токенов по сообщениям. Новые значения берутся только из снимка активного агента.

Лента чата показывает ответ API при демонстрационной ошибке рядом с отправленным сообщением; клиент не сохраняет его в серверной истории. При локально заблокированном запросе также показывается понятная локальная ошибка.

## Проверка

Тесты проверяют оценку payload и лимита, замену оценок фактическим usage, расчёт платной и бесплатной стоимости, накопления, сохранение состояния и изоляцию агентов. HTTP- и клиентские тесты проверяют флажок, локальную блокировку без API-вызова, пробный вызов с отображением ошибки провайдера без изменения контекста, метрики и элементы интерфейса.
