# Компоновка панели метрик — дизайн

## Цель

Сделать раздел «Токены и стоимость» компактным и легко сканируемым, сохранив светлую палитру приложения и все существующие данные.

## Компоновка

Панель начинается со сводки сессии `#token-summary`. Следом размещается раздел `#last-step-metrics` «Метрики последнего хода»: шесть одинаковых `.token-metric-card` в сетке из двух колонок — новое сообщение, история до, вход API, ответ API, история после и контекст/лимит. Название карточки остаётся коротким, а значение становится главным визуальным элементом.

Ниже располагается `#token-growth-chart` «Рост по ходам»: простой SVG-график входных токенов без сторонней библиотеки. Точки идут в порядке `metrics.calls`, а значение Y — `promptTokens`. При нуле записей SVG показывает «Данных пока нет»; при одной записи показывает одну точку без расчётов `NaN`.

Затем контейнер `#token-history-scroll` содержит таблицу `#token-history-table`, прокручиваемую горизонтально на узком экране. Колонки однозначно привязаны к данным: «Ход» — `messageNumber`, «Вход» — `promptTokens`, «Выход» — `completionTokens`, «Всего» — `totalTokens` текущего хода, «Накопленные токены» — `cumulativeTotalTokens`, «Стоимость» — `cost`.

## Настройки и состояния

Учебный лимит и флажок демонстрационного запроса используют обычные подписи с нормальным регистром и компактный flex-ряд; флажок стоит слева от текста. Только при существующем `metrics.lastContextAttempt` показывается отдельная карточка `#context-attempt-card` с её `reason` и, при необходимости, `mode`; новых серверных предупреждений не добавляется.

## Проверка

Тесты статической страницы проверяют новые идентификаторы, секции, SVG-график и заголовки таблицы. Существующие тесты API и метрик не меняются, так как переработка не затрагивает данные и поведение.
