# Панель управления форматом ответа — дизайн

## Цель

Расширить локальный веб-чат DeepSeek для задания второго дня: отправлять одинаковый запрос как без ограничений, так и с управлением форматом, длиной и условием завершения ответа. Пользователь настраивает параметры в правой панели и видит фактический запрос к API.

## Интерфейс

Правая панель сохраняет существующие метаданные и получает новый верхний блок «Настройки ответа»:

- редактируемый `system prompt`;
- выбор формата: текст или JSON;
- максимальное количество токенов (необязательное целое число);
- стоп-последовательность (необязательная строка);
- кнопка сохранения состояния настроек текущей сессии.

Значения применяются ко всем последующим сообщениям выбранной сессии до следующего сохранения. Новая сессия начинает с исходного system prompt и пустых ограничений. В блоке метаданных остаются user prompt, фактически переданный system prompt, JSON запроса к API и статус последнего вызова.

## Данные и API

Каждая сессия хранит объект `settings` со значениями system prompt, response format, max tokens и stop sequence. Объект входит в ответ существующего `GET /api/sessions`, поэтому интерфейс получает настройки при загрузке и переключении сессий.

Интерфейс сохраняет изменения через `PUT /api/sessions/{sessionId}/settings` с телом:

```json
{
  "systemPrompt": "Ты полезный AI-помощник.",
  "format": "text",
  "maxTokens": null,
  "stop": ""
}
```

`format` принимает `text` или `json`; `maxTokens` — `null` или положительное целое число. Сервер обрезает пробелы в `systemPrompt` и `stop`, сохраняет настройки и возвращает `200` с `{ "session": ... }`. Некорректное тело возвращает `400` с `{ "error": "..." }` и не изменяет сессию; неизвестная сессия возвращает `404`.

При отправке сообщения сервер строит `messages` из системного сообщения с текущим prompt и истории диалога. Вызов DeepSeek получает:

- `response_format={"type": "json_object"}` для формата JSON;
- `max_tokens`, только когда задан валидный лимит;
- `stop`, только когда задана непустая стоп-последовательность.

В JSON-режиме к фактическому system prompt добавляется короткая инструкция вернуть только валидный JSON. Этот объединённый prompt отображается в метаданных и входит в отправленный payload. В текстовом формате дополнительная инструкция отсутствует.

## Ошибки и валидация

- `max_tokens` должен быть положительным целым числом; пустое значение сбрасывает ограничение.
- System prompt не может быть пустым после обрезки пробелов.
- Стоп-последовательность обрезается; пустое значение сбрасывает условие завершения.
- Неправильные настройки возвращают JSON с понятным сообщением и не изменяют сохранённые настройки.
- Существующие ошибки API остаются в текущем виде, но метаданные включают уже сформированный payload с настройками.

## Проверки

Автоматические тесты должны подтвердить:

1. исходные настройки появляются у новой сессии;
2. обновлённые настройки сохраняются и возвращаются для текущей сессии;
3. текстовый запрос не содержит необязательных API-параметров;
4. JSON-режим отправляет `response_format`, лимит, стоп-последовательность и JSON-инструкцию в system prompt;
5. неверный лимит и пустой system prompt отклоняются без изменения сессии;
6. HTML содержит элементы управления и существующие метаданные.
