# Тест кейс для скринкаста индекса EPUB дня 21

Цель демонстрации — показать, что одна и та же книга индексируется двумя способами, а поиск возвращает фрагменты с проверяемым источником и разделом. Сценарий рассчитан примерно на 3–4 минуты. Все команды выполняются из корня репозитория в ветке `day-21`.

## Подготовка до записи

Откройте терминал и перейдите в проект:

```bash
cd "/Users/d.fedotova/Мои проекты/AI Adent Challenge"
git branch --show-current
ollama list
```

Ожидается ветка `day-21` и модель `embeddinggemma:latest`. Сервер Ollama уже запущен через Homebrew. Если после перезагрузки он недоступен, выполните `brew services start ollama` до начала записи. Откройте рядом файл `docs/day-21/comparison.md`, чтобы быстро показать результаты запросов.

## Сценарий записи

### 1. Построить индекс

```bash
python3 deepseek-api/document_index.py build
```

Дождитесь последней строки: **40 глав, 603 чанка, 27 235 слов**. Прогресс `Эмбеддинги: …/603` подтверждает, что тексты проходят через локальную модель. Можно сказать: «Мы индексируем русскоязычный EPUB, исключая обложку, оглавление и другие служебные страницы. В одной базе сохраняются обе стратегии и векторы».

### 2. Сравнить стратегии на одном корпусе

```bash
python3 deepseek-api/document_index.py compare
```

Покажите таблицу в терминале. Ожидаемые значения:

| Стратегия | Чанков | Средняя длина | Пересечений разделов |
|---|---:|---:|---:|
| `fixed` | 142 | 220,5 слова | 139 |
| `structural` | 461 | 59,4 слова | 0 |

Затем покажите открытый `docs/day-21/comparison.md`: там сохранены эти показатели и по три результата для каждого из трёх одинаковых запросов. Можно сказать: «Фиксированное окно берёт до 250 слов и иногда пересекает H1–H3. Структурное начинает новый чанк на границе раздела, поэтому чанков больше, но пересечений нет».

### 3. Выполнить один и тот же поиск

```bash
python3 deepseek-api/document_index.py search "Как агенту хранить память проекта между сессиями?" --strategy fixed --top-k 1
python3 deepseek-api/document_index.py search "Как агенту хранить память проекта между сессиями?" --strategy structural --top-k 1
```

Оба первых результата должны ссылаться на `OEBPS/claude-md-memory.xhtml`, главу **«Память проекта»**. У `fixed` показан чанк, начинающийся с раздела «Память проекта»; у `structural` — более точный подраздел **«Решение»**. Команды печатают оценку сходства, главу, путь раздела, источник, ID чанка и фрагмент текста. Оценки в текущем индексе около **0,60** и **0,62** соответственно; после пересборки небольшое изменение чисел допустимо.

Можно сказать: «Запрос и книга одинаковые. Меняется только способ разбиения. По этим нескольким примерам нельзя объявить одну стратегию всегда лучшей, но видно, как границы разделов влияют на выдачу».

## Критерии успешного показа

- `build` завершается без ошибки и создаёт `docs/day-21/index.sqlite3`.
- `compare` показывает обе стратегии для 40 глав и обновляет `docs/day-21/comparison.md`.
- Оба `search` возвращают непустой результат с источником, разделом и фрагментом; в этом сценарии первым находится глава «Память проекта».

Если запись нужно сократить, заранее соберите индекс и начните с `compare`. Тогда прогресс генерации эмбеддингов останется за кадром, а различие стратегий и живой поиск сохранятся в демонстрации.
