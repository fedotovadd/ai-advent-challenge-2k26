## Автоматические проверки

Команда из `deepseek-api`:

```bash
.venv/bin/python -m unittest discover -s tests
```

Результат: **233 теста, OK**, включая 20 тестов планировщика/MCP. HTTP-тестам
нужно разрешение создавать локальные sockets. Первый запуск в ограниченной
песочнице завершился ошибками bind; с разрешённым loopback все тесты прошли.

Дополнительно проверен синтаксис JavaScript страницы и MCP-контролов через
`node --check`; `git diff --check` не выявил проблем.

Покрыты: запуск не раньше срока, однократность, период и пропущенные интервалы,
повторное открытие SQLite, захват двумя worker, восстановление просроченного lease,
отклонение устаревшего результата, отмена до/во время исполнения, правильный
running-статус после аварии, тайм-аут, API-ошибка и следующий успешный запуск,
неожиданная ошибка без утечки её текста, накопительная сводка при ограниченной
истории, строгие MCP-параметры, неизвестный ID, размер результата менее 16 KiB,
разрешение только точного локального MCP URL, HTTP API и application lifespan.

Независимая проверка кода нашла неверный running-статус отменённой задачи после
остановки worker. Ошибка воспроизведена отдельным падающим тестом и исправлена.

## Реальный HTTP/MCP и GitHub

Артефакт: [live-results.json](live-results.json).

- Настоящий `AgentRegistry` вызвал `schedule_repository` через общий `McpRegistry`
  и HTTP MCP по адресу `http://127.0.0.1:8002/mcp`.
- В этом прогоне только ответ модели был подменён; SQLite, worker, транспорт MCP
  и GitHub API настоящие.
- Задача: `octocat/Hello-World`, задержка 3 секунды, период 10 секунд.
- Сразу после создания успешных проверок было 0. Затем клиентские MCP-сессии
  закрыты, тест ожидал 17 секунд.
- После ожидания: **2 успеха, 0 ошибок**, 3828 звёзд и 6896 форков, изменение
  обоих счётчиков равно 0. Значения отражают момент прогона, не являются эталоном.
- Задача отменена через MCP. Сводка и история сохранены.

## Реальная модель → MCP → фоновая задача → сводка

Артефакт: [live-llm-results.json](live-llm-results.json).

- Модель **deepseek-v4-flash** самостоятельно вернула вызов `schedule_repository`
  с `owner=octocat`, `repo=Hello-World`, `delay_seconds=3`, `interval_seconds=null`.
- Задание исполнено один раз: **1 успех, 0 ошибок**. SQLite сохранила результат.
- На следующем ходе та же модель вызвала `get_schedule_summary` и получила
  фактические 3828 звёзд и 6896 форков, статус `completed` и `next_run_at=null`.
- В ответе модель корректно пояснила: нулевая дельта обусловлена первым
  наблюдением, повторов не будет. Оба tool call и ответы сохранены в артефакте.
- Этот прогон использует настоящие DeepSeek API, AgentRegistry, MCP HTTP,
  SQLite, worker и GitHub API. Ключи и HTTP-заголовки в артефакты не записывались.

## Границы проверки

Полный 24-часовой прогон и установка launchd не выполнялись. Постоянная работа
требует включённого компьютера/сервера и запущенного процесса. Не заявляется
исполнение во сне, после выключения или точность запуска под любой нагрузкой.

Визуальная проверка страницы в браузере пока не выполнена: основной браузерный
инструмент не инициализировался; запасной инструмент получил отказ автоматической
проверки разрешений на открытие локальной страницы из-за предполагаемой передачи
сохранённых расписаний браузерному инструменту. Запрошено разрешение пользователя.
HTTP и JavaScript проверены без обхода запрета на браузерное действие.
