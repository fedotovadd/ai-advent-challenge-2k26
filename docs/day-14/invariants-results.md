# День 14 — инварианты и ограничения состояния

У каждого агента появился отдельный сохраняемый массив `context.invariants`.
Он не является частью истории диалога или ветки контекста, поэтому сохраняется
при переключении ветки и перезапуске приложения.

## Команды

```text
/invariant Использовать Kotlin и Ktor
/invariant Не использовать Python
/invariants
/remove-invariant 1
/clear-invariants
```

Текст после `/invariant` — свободная формулировка правила; двоеточие не
нужно. Дубликаты, пустые правила, слишком длинный текст и противоречивые
явные ограничения стека отклоняются локально.

## Как агент соблюдает ограничения

Перед профилем, задачей, памятью и историей в system prompt добавляется блок
`[ИНВАРИАНТЫ]`, объявляющий правила приоритетными. Явная просьба «Реализуй на
Python» при правиле «Не использовать Python» блокируется ещё до вызова
провайдера: HTTP API возвращает `400`, объясняет нарушенное правило, а история
не меняется. Если запрещённую технологию предлагает сама модель, её ответ
заменяется понятным отказом до показа пользователю.

Детерминированная проверка понимает явные формулировки «использовать X»,
«только X», «не использовать X» и «без X». Свободные бизнес-правила также
сохраняются и передаются модели как приоритетный контекст, но не выдаются за
полную машинную семантическую проверку.
