# День 13 — состояние задачи

Реализован сохраняемый конечный автомат задачи в `context.taskState`:
`PLANNING → EXECUTION → VALIDATION → DONE`.

## Сценарий проверки

1. `/task Статья` создаёт задачу в `PLANNING`; команда не отправляется модели.
2. В ответ на обычное сообщение агент может вернуть `[[TASK_PLAN]]` с
   Markdown-планом. Приложение сохраняет `agent-1-task-1.md` в каталоге
   `data/task-plans`, показывает Markdown в чате и ждёт `/execute`.
3. `/execute` начинает `EXECUTION`. Завершение каждого шага помечается
   служебной меткой модели; последний шаг автоматически начинает `VALIDATION`.
4. `/pause` сохраняет этап, шаг и ожидаемое действие. Обычное сообщение на
   паузе отклоняется без вызова модели; `/resume` продолжает тот же шаг.
5. `/status` выводит этап, прогресс, текущий и выполненные шаги, а также
   ожидаемое действие. В `VALIDATION` финальная метка переводит задачу в
   `DONE` и показывает уведомление о завершении.

Проверки: `python3 -m unittest discover -s tests -v` и
`python3 -m py_compile agent.py web.py task_state.py` из `deepseek-api`.
