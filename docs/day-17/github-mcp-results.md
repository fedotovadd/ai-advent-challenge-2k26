# День 17 — результаты проверки GitHub MCP

Дата: 26 сентября 2026. Модель: `deepseek-v4-flash`, обычный текст, thinking disabled.

## Сквозной прогон

В тестовой копии приложения на `http://127.0.0.1:8017` через вкладку MCP
подключён собственный сервер `http://127.0.0.1:8001/mcp`. Сервер реально
обращался к GitHub REST API без GitHub-токена. Использован настоящий DeepSeek.

1. Агент 1 получил запрос о `modelcontextprotocol/python-sdk`, сам вернул
   tool call, инструмент `get_repository` получил параметры
   `{"owner":"modelcontextprotocol","repo":"python-sdk"}`. Итоговый ответ
   использовал описание, язык Python, 24 406 звёзд и ссылку из GitHub.
2. Создан Агент 2, без дополнительной настройки MCP отправлен запрос об
   `octocat/Hello-World`. Модель вызвала тот же инструмент и корректно сообщила,
   что основной язык не указан (`language=null`), вернула ссылку.
3. В обоих ходах выполнены по два запроса DeepSeek и по одному MCP-вызову.
   Usage первого хода — 1779 токенов, второго — 1700.

Полные аргументы, MCP-результаты, запросы модели с парой assistant tool_calls /
role=tool и ответы сохранены в [live-results.json](live-results.json).
Число звёзд — наблюдение на момент проверки, не постоянный ожидаемый результат.
API-ключи и HTTP-заголовки в артефакт не включены.

После переноса в исходную ветку `day-17` повторён живой запрос: один MCP-вызов,
два запроса DeepSeek, 2002 токена; сведения использованы в ответе.

## Ошибки

- Запрос несуществующего `octocat/codex-day17-nonexistent-repo-20260926`
  вернул MCP `isError=true`; модель объяснила, что репозиторий не найден.
- После остановки MCP-процесса следующий запрос вернул понятное сообщение
  о недоступном подключении. Агент не выдумал число звёзд.
- Эти два сценария также записаны в `live-results.json`.
- После перезапуска список серверов и истории восстановлены; сервер показан
  отключённым и успешно подключён повторно через ту же вкладку.

## Автоматическая проверка

Итог в изолированной рабочей копии и в исходном окружении ветки `day-17`: **213 тестов, OK**.

Команда: `python -m unittest discover -s tests -v` из `deepseek-api`.
Проверки охватывают регистрацию/схему/результат MCP, GitHub HTTP-ошибки,
общие подключения, два сервера с одинаковыми именами инструментов,
disconnect во время хода, tool result pairing, лимиты и ошибки JSON,
учёт промежуточных ответов и partial failure, миграцию состояния версии 10,
откат settings/task, HTTP API и безопасное отображение в интерфейсе.

Браузерная проверка выполнена через встроенный браузер Codex. Основной
browser-use runtime не запустился из-за отсутствующего native build classic-level;
для проверки использован доступный browser-control fallback.
