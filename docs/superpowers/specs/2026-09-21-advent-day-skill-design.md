# Универсальный skill для нового дня AI Advent Challenge — дизайн

## Цель

Создать личный Codex skill `implementing-advent-day`. Он принимает номер дня и
текст очередного задания AI Advent Challenge, изолирует работу в ветке
`day-XX`, выбирает только подходящие доступные skills и доводит реализацию до
проверяемого результата. После этого он добавляет понятное описание решения в
`deepseek-api/README.md`.

## Границы

Skill предназначен для повторяющихся, различающихся по тематике заданий этого
репозитория. Он не предполагает заранее ни протокол, ни язык, ни внешнюю
библиотеку: это определяется текстом конкретного задания.

Skill не выполняет `git commit`, push, создание PR или установку пакетов с
доступом к сети без отдельного разрешения пользователя. Он также не меняет
чужие незакоммиченные файлы и останавливается, если имя ветки `day-XX` уже
занято или базовая ветка не определена однозначно.

## Входные данные

Пользователь передаёт номер дня и полную формулировку. Например, для Day 16:

```text
День 16. Подключение MCP
...
```

Номер нормализуется до двух цифр: `16` становится `day-16`. Если номер или
требования отсутствуют, skill запрашивает только недостающий элемент до начала
изменений.

## Рабочий поток

1. Проверить репозиторий, текущую ветку и статус рабочей директории. Найти
   согласованную базовую ветку; по умолчанию это `main` только если она
   существует и пользователь не указал другую.
2. Создать ветку `day-XX` от базовой точки. При существующей ветке или
   конфликтующих локальных изменениях не переключаться и запросить решение.
3. Разобрать задание на изменения, проверяемые критерии и документацию.
   Активировать релевантные skills: обязательны skills процесса разработки;
   предметные skills подключаются лишь когда их триггеры подходят задаче.
4. Реализовать минимальное решение через тесты, затем выполнить подходящую
   проверку: unit/integration тест, команда запуска или оба варианта.
5. Обновить `deepseek-api/README.md`: добавить пункт оглавления и раздел
   текущего дня с назначением, запуском, составом решения, ограничениями и
   способом проверки. Описание должно отражать фактическую реализацию, а не
   копировать текст задания.
6. Проверить diff, отсутствие ошибок форматирования и соответствие каждого
   требования заданию. Сообщить результаты и перечислить созданные/изменённые
   файлы.

## Пример маршрутизации: День 16 — MCP

Skill распознаёт задачу как локальную интеграцию MCP. Он сначала выясняет
существующие зависимости и доступный транспорт, затем выбирает самый малый
подходящий MCP SDK или локальный MCP-сервер. Проверка должна доказывать, что
код действительно устанавливает соединение и получает непустой либо ожидаемый
список доступных инструментов; тест не подменяет сам MCP-клиент моками. README
документирует зависимость, способ запуска, вывод списка tools и результат
проверки.

## Проверка самого skill

Перед публикацией skill проходит: проверку метаданных штатным
`quick_validate.py`, независимый сценарий с вымышленным днём и ручную проверку
границ — занятой ветки, грязной рабочей директории, отсутствующего номера дня
и задания, которому не нужен доменный skill.
