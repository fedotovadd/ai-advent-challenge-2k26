# День 27 — локальная LLM в веб-чате

## Цель и исходное состояние

Встроить локальную генеративную модель в существующее веб-приложение `deepseek-api`, чтобы пользователь мог выбрать `qwen2.5:1.5b`, отправить сообщение и увидеть ответ в обычном чате. В этом режиме приложение должно работать без ключей DeepSeek и Z.AI и без обращения к облачной модели.

День 26 уже подтвердил загрузку `qwen2.5:1.5b` в Ollama и ответы через локальный HTTP API; фактические результаты записаны в `docs/day-26/results.md`. На момент подготовки этой спецификации `http://127.0.0.1:11434/api/tags` не отвечает, поэтому доступность сервиса и модели надо проверить заново перед сквозным тестом. День 27 добавляет именно интеграцию с приложением: прямой вызов `curl` или `ollama run` из дня 26 не засчитывается как результат этого дня.

## Выбор приложения и подхода

| Вариант | Плюсы | Минусы |
|---|---|---|
| Добавить Ollama в существующий веб-чат через OpenAI-совместимый API **(выбран)** | Используются готовые агенты, история, форма отправки и общий адаптер `providers.ask_model`; пользователь видит ответ в приложении | Нужно расширить список моделей и обработку ошибок; учитывать общие настройки чата |
| Создать отдельный минимальный CLI | Быстро и мало зависимостей | Дублирует уже существующее приложение; слабее демонстрирует интеграцию в текущий продукт |
| Написать отдельный клиент нативного `/api/chat` | Доступны специфичные поля Ollama | Потребуется преобразовывать ответы и метрики в контракт существующего агента |

Официальная [документация Ollama по совместимости с OpenAI](https://docs.ollama.com/api/openai-compatibility) описывает локальный `/v1/chat/completions` и поддерживает нужные чату поля `messages`, `temperature`, `response_format`, `stop`, `max_tokens`. Это позволяет сохранить существующий Python SDK `openai` и интерфейс `ask_model(payload, **options)`.

## Пользовательский сценарий

1. Пользователь запускает Ollama с уже загруженной `qwen2.5:1.5b`, затем запускает `deepseek-api/main.py` обычным способом и открывает `http://127.0.0.1:8000`.
2. В настройках агента выбирает пункт «Локально · qwen2.5:1.5b». Выбор сохраняется вместе с настройками этого агента и отображается в заголовке и списке агентов. У других агентов модель не меняется.
3. Отправляет обычное сообщение. Приложение показывает состояние ожидания, отправляет историю и настройки выбранного агента на локальный сервер Ollama, получает текст ответа и добавляет его в тот же диалог. Следующее сообщение учитывает предыдущую пару реплик по текущей стратегии контекста.
4. При остановленной Ollama, отсутствующей модели, превышении времени ожидания или пустом ответе пользователь видит понятную ошибку. По существующему правилу чата отправленное сообщение остаётся в истории без ответа ассистента; новая отправка считается новым ходом, а автоматического повторения нет. Приложение не переключается на облачный провайдер автоматически.

Для демонстрации достаточно обычного чата. Режимы «День 3», RAG-CLI, исследовательский pipeline и MCP-инструменты не входят в приёмку дня 27. Для локальной модели вызов MCP уже выключен текущим условием `model.startswith("deepseek-")`; это поведение нужно сохранить. Облачные модели остаются доступными при явном выборе, но локальный сценарий не требует их ключей и сетевого доступа к ним.

## Поток данных и изменения в коде

`Браузер → POST /api/agents/{id}/messages → Agent.respond → providers.ask_model → http://127.0.0.1:11434/v1/chat/completions → Agent → браузер`.

- `deepseek-api/providers.py`: маршрутизация по точному имени `qwen2.5:1.5b`. Для него создать `OpenAI(base_url="http://127.0.0.1:11434/v1/", api_key="ollama", ...)`. Строка `ollama` — требуемое SDK фиктивное значение, локальный сервер его игнорирует; переменные `DEEPSEEK_API_KEY` и `ZAI_API_KEY` не читаются. Локальный адрес фиксирован для этой учебной интеграции, без произвольного URL из браузера. Для локального вызова задать конечный timeout с запасом на холодную загрузку модели и отключить автоматические повторные запросы, чтобы одна отправка не превращалась в несколько генераций. Сохранить прежний контракт результата: `content`, `usage`, `tool_calls`, `message`.
- `deepseek-api/agent.py`: добавить точное имя модели в `MODELS`, запись в `MODEL_CAPABILITIES` и отсутствие облачного тарифа в `MODEL_PRICING`. Консервативный лимит приложения — 4096 токенов контекста и максимум 1024 токена ответа; перед реализацией сверить его с фактическими настройками локальной модели. Если пользователь не указал `maxTokens`, только для локальной модели агент явно передаёт `max_tokens=512` и резервирует столько же токенов при проверке контекста. При заданном `maxTokens` агент передаёт и резервирует выбранное значение, не выше 1024. Параметр должен присутствовать и в метаданных фактического запроса. Существующие валидация настроек, метрики, сохранение истории и изоляция агентов должны работать без изменения формата файла состояния. Для этой модели стоимость облачного API равна нулю; это не утверждение об отсутствии затрат вычислительных ресурсов.
- `deepseek-api/static/index.html`: добавить выбор локальной модели в селектор, явно обозначить её как локальную. Ответ по-прежнему выводится в существующей ленте сообщений, название выбранной модели — в заголовке и списке агентов. Рядом с метрикой стоимости для локальной модели пояснить, что «Бесплатно» означает отсутствие оплаты облачного API, а затраты компьютера не учитываются. Не выводить пользовательский текст или ответ через `innerHTML`.
- `deepseek-api/web.py` и слой ошибок: для локальной модели переводить недоступность Ollama, отсутствие `qwen2.5:1.5b` и timeout в понятные сообщения с указанием локального сервиса; сохранить снимок агента и существующее правило хранения неотвеченного сообщения пользователя. Устранить неверный текст «Не удалось получить ответ DeepSeek» именно для локального режима. Ошибка не должна выглядеть как успешный ответ модели или инициировать облачный fallback.
- `deepseek-api/README.md`: добавить короткую инструкцию запуска Ollama, проверки наличия модели, выбора модели в веб-чате и работы без ключей облачных API.

Настройки `systemPrompt`, температура, формат, `maxTokens` и `stop` передаются через существующий контракт OpenAI-совместимого API. Существующие дополнительные вызовы агента для сжатия или работы с фактами, если пользователь выбрал такие режимы, должны идти через тот же выбранный локальный адаптер. Для приёмочного сценария использовать стратегию контекста по умолчанию (`sliding_window`) и обычный текст: качество JSON, сводок и фактов компактной модели в этот день отдельно не оценивается.

## Границы автономности и безопасность

- Для локального режима единственный адрес генерации — loopback `127.0.0.1:11434`; никакие запросы к `api.deepseek.com`, `api.z.ai` или облачному адресу Ollama не допускаются. Имена с суффиксом `:cloud` не выбираются.
- Нет скрытого резервного провайдера. Если Ollama не работает, модель отсутствует или ответ некорректен, запрос завершается ошибкой.
- Секреты облачных провайдеров не нужны и не должны попадать в payload, браузер или локальный лог. Никакая новая телеметрия не добавляется.
- История и настройки сохраняются по существующим правилам приложения. Выбор локальной модели не меняет ранее сохранённых агентов с облачными моделями.

## Проверка и критерии приёмки

**Автоматические проверки:**

1. Тест адаптера с подменённым `OpenAI` подтверждает точный локальный `base_url`, фиктивный ключ, имя модели, пересылку `messages` и настроек, а также отсутствие чтения облачных ключей. Отдельный тест подтверждает, что облачные модели сохраняют прежнюю маршрутизацию.
2. Тесты агента и HTTP проверяют выбор и сохранение `qwen2.5:1.5b`, ответ в истории, независимость двух агентов, отсутствие MCP-вызова для локальной модели, передачу `max_tokens=512` по умолчанию и корректные ошибки при недоступной Ollama, отсутствующей модели, timeout и пустом ответе. После ошибки в истории есть сообщение пользователя без ответа ассистента; автоматического повторного вызова нет.
3. Прогнать профильные тесты и полный `python -m unittest discover -s tests -v`; устранить регрессии.

**Живая демонстрация без облачных ключей:**

1. Проверить `ollama list` и `GET http://127.0.0.1:11434/api/tags`; там должна быть `qwen2.5:1.5b`. Если сервис остановлен, запустить существующую Ollama. Загрузка модели из сети не входит в офлайн-демонстрацию: она выполнена в день 26.
2. Запустить веб-приложение в окружении без `DEEPSEEK_API_KEY` и `ZAI_API_KEY`, выбрать локальную модель и отправить два связанных русскоязычных сообщения. Оба ответа должны появиться в ленте; второй должен получить предыдущую реплику в контексте.
3. Подтвердить по перехваченному или отладочному вызову адаптера, что генерация адресована только `127.0.0.1:11434`. По возможности повторить сценарий с отключённым внешним интернетом. Наличие ответа в браузере при отсутствии облачных ключей и отсутствие обращений к облачным API — обязательные признаки выполнения.
4. Остановить Ollama и повторить запрос: пользователь должен увидеть ошибку локального сервиса без ответа, якобы полученного от модели, и без облачного fallback. После запуска Ollama повторный запрос должен работать.

Фактические команды, снимок настроек, запросы и полученные ответы, адрес вызова, результаты тестов и проверку отказа сохранить в `docs/day-27/results.md`. Ошибку или недоступную среду отметить как невыполненный пункт, а не подменять ожидаемым результатом.
