# День 18 — планировщик GitHub-сводок

## Назначение

Продолжение дня 17: агент через MCP создаёт отложенную или периодическую проверку
публичного репозитория GitHub. Фоновый процесс исполняет расписание независимо от
чата и сохраняет результаты. Выбор сценария и реализация делегированы пользователем.
Напоминания проще, но хуже демонстрируют агрегацию; произвольные LLM-задачи
требуют лишних расходов и управления контекстом. Поэтому используем GitHub-сводку.

## Контракт

- Отдельный сервер `scheduler_mcp_server.py`, адрес `http://127.0.0.1:8002/mcp`.
- Инструменты `schedule_repository`, `list_schedules`, `get_schedule_summary`,
  `cancel_schedule`. Общий каталог MCP уже делает их доступными всем агентам.
- Задание содержит owner/repo, задержку первого запуска и необязательный период.
  Без периода выполняется одна проверка; с периодом — повторяющиеся проверки.
- SQLite хранит задания, счётчики, первый/последний успешный снимок и последние
  100 попыток каждого задания. Сводка содержит успешные/неуспешные проверки,
  изменения звёзд и форков, времена фактических наблюдений, последнюю ошибку.
- Read-only страница на `http://127.0.0.1:8002/` обновляет сводки автоматически.
  Каждый результат также печатается в stdout в JSON. Для фонового сбора LLM не нужен.

## Выполнение и сбои

Worker запускается в lifespan HTTP-приложения, а не клиентской MCP-сессии.
Все времена UTC. Просроченное задание исполняется один раз; пропущенные интервалы
не воспроизводятся лавиной запросов. Следующая дата сохраняет исходную сетку.
Транзакционный захват с lease и токеном защищает от двух исполнителей. После
аварии задание повторяется по окончании lease; сетевой read-only запрос может
повториться, но результат для одного scheduled_at сохраняется один раз.
Timeout запроса меньше lease. Ошибка GitHub сохраняется как неуспешная попытка;
периодическая задача продолжает работу. Отмена прекращает будущие запуски,
уже начавшаяся проверка может завершиться. История после отмены доступна.

## Эксплуатация и проверка

Один процесс работает, пока запущен Python; для постоянной работы нужен supervisor
и включённый компьютер/сервер. Предоставить пример launchd для macOS. Не обещать
работу во сне или на выключенном компьютере. Отключение MCP в чате не отменяет задачи.
Проверить сохранение/перезапуск, пропуски, ошибки/восстановление, отмену, конкуренцию,
реальные MCP list/call, lifespan без клиента, HTTP-страницу и общую регрессию.
