# Инварианты состояния агента — дизайн

## Цель

Добавить агенту независимый от диалога сохраняемый слой инвариантов. Агент должен включать эти правила в каждый запрос к модели и не выдавать ответ, который им противоречит.

## Команды

Текст после `/invariant ` сохраняется как новый инвариант без дополнительного синтаксиса:

```text
/invariant Использовать Kotlin и Ktor
/invariant Не использовать Python
```

Служебные команды не конфликтуют со свободным текстом:

```text
/invariants
/remove-invariant 1
/clear-invariants
```

Нумерация при просмотре начинается с 1. Неверные номера и пустые значения возвращают понятную ошибку, не меняя состояние.

## Архитектура и поток данных

Новый модуль `invariants.py` владеет форматом данных, командами, ограничениями размера, формированием блока промпта и детерминированной проверкой нарушений. В `context` агента появится поле `invariants`, отдельное от `messages`, памяти и состояния задачи; оно попадёт в сохранённый JSON и восстановится после перезапуска.

При обычном сообщении агент:

1. Загружает сохранённые инварианты из контекста.
2. Выполняет раннюю проверку пользовательского текста. При обнаружении явного конфликта не вызывает провайдера и возвращает отказ с правилами и предложением соблюдать их.
3. Добавляет блок `[ИНВАРИАНТЫ]` в системный промпт, требуя явно сверять решение с каждым правилом.
4. Проверяет ответ модели до сохранения в истории. Нарушающий ответ заменяется объяснением отказа и не сохраняется как ответ модели.

Проверка в первой версии основана на нормализованном сопоставлении фраз: формулировки «использовать X», «только X», «не использовать X» и «без X» выводят требование или запрет для технологии. Это покрывает демонстрационные конфликты из задания, остаётся прозрачным для пользователя и не выдаёт эвристический анализ за полную семантическую верификацию произвольных бизнес-правил.

## API и интерфейс

Команды идут через существующий endpoint сообщений. Они выполняются локально: не добавляются в историю и не отправляются в LLM. Снимок агента возвращает `context.invariants`, поэтому будущий интерфейс сможет их отображать; в Day 14 отдельная форма не требуется. Ответы-команды будут включать актуальный список инвариантов.

## Отказ и сохранность

Отказ отвечает по-русски, указывает конкретные нарушенные правила и приглашает переформулировать запрос в допустимых рамках. При раннем конфликте пользовательское сообщение не записывается в историю. При нарушении ответа пользовательское сообщение сохраняется, но вместо небезопасного ответа сохраняется текст отказа; это сохраняет прозрачную историю разговора и не показывает запрещённую рекомендацию.

## Проверка

Тесты должны доказать: свободное добавление инварианта, просмотр/удаление/очистку и их сохранение; присутствие блока в системном промпте; ранний отказ без вызова провайдера при «Не использовать Python»; замену ответа модели с запрещённой технологией; корректную обратную совместимость сохранённого состояния без поля `invariants`; HTTP-обработку команд.
