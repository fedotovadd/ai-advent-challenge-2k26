# Подключение публичного MCP по URL — дизайн

## Цель

Расширить вкладку MCP: пользователь вводит URL публичного MCP-сервера по
HTTPS, нажимает «Подключить» и получает список его инструментов. Открытие
вкладки ничего не подключает. Инструменты по-прежнему не передаются DeepSeek
и не вызываются из чата.

## Границы

- Поддерживаются только удалённые Streamable HTTP MCP-серверы с `https://`.
- Локальные адреса (`localhost`, IP-адреса, домашняя сеть) и `http://` не
  поддерживаются.
- URL, инструменты и состояние подключения не сохраняются между запусками.
- OAuth, API-ключи, локальный `stdio` и вызовы MCP-инструментов не входят в
  эту задачу.

## Поток данных

На вкладке MCP находится поле URL с DeepWiki как примером и кнопка
«Подключить». По нажатию `mcp-controls.js` отправляет
`POST /api/mcp/tools` с JSON `{"url": "..."}`. `web.py` проверяет
same-origin, размер и точную схему тела, затем передаёт URL в
`mcp_client.list_tools(url)`.

Клиент проверяет абсолютный HTTPS URL без учётных данных, query и fragment;
IP-литералы и DNS-имена, которые разрешаются в непубличные адреса,
отклоняются. Затем он создаёт MCP Streamable HTTP-сессию, выполняет
инициализацию и `list_tools()`. Ответ содержит только имя и описание
инструмента. Ошибка URL возвращается как 400, ошибка подключения или
протокола — как 502.

## Интерфейс

Пока идёт запрос, кнопка отключена и показывает «Подключение…». После успеха
видны статус «Подключение установлено», количество и карточки инструментов.
Ошибки выводятся в том же статусе. Текст от сервера вставляется только через
`textContent`.

## Проверка

Unit-тесты покрывают валидацию URL, последовательность MCP
initialize/list_tools и описание по умолчанию. HTTP-тесты покрывают
успешное подключение с внедрённым клиентом, 400, 502 и same-origin. UI-тесты
проверяют поле URL, передачу JSON только по кнопке и безопасный рендеринг.
Ручная проверка выполняется с DeepWiki и подтверждает непустой список
инструментов.
