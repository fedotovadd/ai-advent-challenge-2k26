# День 23 — cross-encoder reranking и query rewrite

## Цель

Реализовать конвейер со слайда: **исходный вопрос → bi-encoder Top-20 → cross-encoder rerank и Top-5 → LLM-ответ**. Добавить порог отсечения нерелевантных результатов, query rewrite после первого поиска и сравнение режимов на десяти вопросах дня 22. Реальный cross-encoder оценивает пару «запрос + чанк» совместно; повторная сортировка делается по его score, а не по cosine similarity.

Используется готовый структурный индекс `docs/day-21/index.sqlite3`, его модель Ollama `embeddinggemma`, текущий генератор ответа и контрольные вопросы дня 22. Индекс, EPUB, веб-интерфейс и результаты дня 22 не изменяются.

## Три режима сравнения

| Режим | Первый поиск | После Top-20 | Контекст ответа |
|---|---|---|---|
| `baseline` | Исходный вопрос | Первые 5 по cosine, без второго этапа | Исходный вопрос + эти 5 чанков |
| `reranked` | Исходный вопрос | Cross-encoder оценивает 20 пар с исходным вопросом; порог; Top-5 по новому score | Исходный вопрос + выбранные чанки |
| `rewritten` | Исходный вопрос | LLM переписывает вопрос по краткому обзору Top-20; cross-encoder оценивает 20 пар с переписанным запросом; тот же порог; Top-5 | Исходный вопрос + выбранные чанки |

Это **один** bi-encoder поиск во всех режимах. Rewrite стоит после Top-20 и влияет на cross-encoder, но не меняет состав двадцати кандидатов. Повторный поиск после rewrite не входит в этот вариант схемы. Так сравнение `baseline → reranked` измеряет второй этап, а `reranked → rewritten` — эффект rewrite на том же пуле документов.

## Cross-encoder и порог

Локальная модель по умолчанию — [`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1), многоязычный reranker из семейства Sentence Transformers, обученный на mMARCO, где есть русский. Он загружается лениво через `sentence_transformers.CrossEncoder`, поэтому прежние команды дня 22 не требуют новой зависимости. Первую загрузку весов необходимо выполнить при доступе к Hugging Face; затем модель работает локально. Python-зависимости для дня 23 выделены в `deepseek-api/requirements-rerank.txt`.

Пара к модели: `(search_query, title + section + text)` для каждого из 20 кандидатов. Для `CrossEncoder.predict` явно задаётся `torch.nn.Sigmoid()` как функция активации: возвращается один конечный score в `[0,1]` на пару. Эта шкала **не является калиброванной вероятностью**. Сортировка по убыванию score, при равенстве — по исходному bi-encoder рангу и `chunk_id`. Порог `min_rerank_score` по умолчанию `0.50`, доступен в CLI в диапазоне `[0,1]`. Из прошедших порог берутся не более `top_k_after=5`. До этапа — `top_k_before=20`. Если ни один чанк не прошёл, возвращается фиксированный ответ о недостатке сведений без вызова модели ответа. Порог фиксируется до итогового прогона и оценивается на его результатах; отсутствие улучшения или потеря нужного источника показываются в отчёте.

Если библиотека/модель недоступна, `reranked` и `rewritten` дают понятную ошибку с инструкцией установки; тихого перехода на cosine или LLM-эвристику нет. Неожиданное число scores, NaN/бесконечность и пустой ответ модели — ошибки. Текст длиннее лимита модели обрезается токенизатором cross-encoder (`max_length=512`); в отчёте это указывается как ограничение.

## Rewrite после первого этапа

Для режима `rewritten` LLM получает исходный вопрос и до 20 кратких карточек кандидатов (заголовок, раздел, до 200 символов текста; общий лимит на вход). Инструкция: дать **одну** поисковую формулировку по-русски, сохранить смысл, отрицания и конкретные сущности, не добавлять фактов из фрагментов и не отвечать на вопрос. Вызов использует выбранную для ответа модель, температуру 0 и именованный аргумент `max_tokens=120` у `providers.ask_model`. Пустой/многострочный/чрезмерно длинный rewrite — ошибка. Документальные карточки считаются данными, а не инструкциями. Оригинальный и переписанный запросы сохраняются; LLM для финального ответа всегда получает исходный вопрос.

## Интерфейсы

- `deepseek-api/rag_reranker.py`: `CrossEncoderReranker` с ленивой загрузкой модели, чистая функция `rerank_candidates`, функция `rewrite_query` с подменяемым `ask`.
- `deepseek-api/rag_agent.py`: выделенный общий помощник для неизменного промпта ответа дня 22.
- `deepseek-api/rag_day23.py`: `answer_question_day23`, команды `ask` и `evaluate`. Общие `--index` и `--ollama-url` задаются до команды; `--top-k-before`, `--top-k-after`, `--min-rerank-score`, `--reranker-model`, `--model` — после неё.
- `deepseek-api/tests/test_rag_reranker.py`, `deepseek-api/tests/test_rag_day23.py`: модульные и интеграционные тесты с подставными внешними сервисами.
- `docs/day-23/results.json`, `docs/day-23/comparison.md`: отдельный живой прогон и ручная оценка.
- `deepseek-api/README.md`: установка и запуск дня 23.

Результат одного вопроса хранит исходный вопрос, режим, поисковый запрос для второго этапа, кандидатов Top-20 с bi-score/рангом, rerank-score/рангом для двух улучшенных режимов, выбранные чанки, ответ, статус, параметры и идентификаторы моделей. Векторы SQLite в JSON не попадают.

## Оценка и восстановление

Для каждого из десяти вопросов выполняются все три режима с одной моделью ответа и тем же индексом. Отчёт показывает изменение порядка, источники/score до и после, попадание ожидаемой главы, полноту 0–2 и ручную оценку опоры на текст (`да`/`частично`/`нет`). Отдельно фиксируются улучшения, ухудшения и равные результаты. Уменьшение числа чанков само по себе не считается повышением качества.

После каждого полностью законченного вопроса записывается `.partial`. Настройки, хеш вопросов и индекса, адрес Ollama, имя embedding-модели и имя cross-encoder проверяются при возобновлении. Итоговый JSON записывается первым, черновой Markdown вторым; `.partial` удаляется последним. Повторный запуск после сбоя между этими шагами сверяет существующий JSON, дописывает отсутствующий отчёт либо только убирает устаревший `.partial`, не перезаписывая отредактированный вручную Markdown. Без `--overwrite` существующие результаты защищены. Ручной отчёт считается завершённым после заполнения оценок, даты и статуса «проверено».

Проверки вне книги («Какая погода завтра в Москве?» и «Сколько стоит билет на поезд Москва — Казань сегодня?») выполняются отдельно от десяти вопросов. Содержательный ответ на них фиксируется как неудача отсечения; порог после итогового прогона не подгоняется задним числом. Ограничения: модель может неверно переставить релевантные чанки, порог не является вероятностным критерием, rewrite не способен вернуть документ вне исходных Top-20.
