# День 25 — мини-чат с RAG и памятью задачи

## Цель и границы

Добавить отдельный CLI-чат поверх готового индекса EPUB и механизма проверяемых цитат дня 24. Каждый ввод пользователя, кроме служебных команд, запускает новый поиск. Чат сохраняет историю и состояние задачи между запусками, отвечает по найденным фрагментам и всегда печатает раздел «Источники». Если оснований для ответа нет, в этом разделе явно указано «нет».

Используются существующие `docs/day-21/index.sqlite3`, `document_index.search_index`, `rag_reranker.rerank_candidates`, `providers.ask_model` и проверка цитат `rag_citations.validate_answer_json`. Индекс, EPUB, веб-чат и прежние результаты не меняются. Загрузка произвольных документов и полноценная многопроцессная работа с одной сессией не входят в задание.

По выбору пользователя CLI-чата и сценарный прогон по умолчанию используют `deepseek-v4-flash` с `DEEPSEEK_API_KEY`; настройки и результаты дня 24 не меняются.

## Пользовательский сценарий

`rag_chat.py chat --session <имя>` создаёт или продолжает сессию. Пользователь вводит реплики до `/exit`. `/state` показывает цель, уточнения, ограничения и термины вместе с номерами реплик-источников. `/history` показывает сохранённый диалог; `/exit` ничего не удаляет. По умолчанию SQLite-файл хранится в игнорируемом Git каталоге `deepseek-api/data/`; путь можно задать через `--db`.

После ответа CLI печатает `Ответ`, `Источники`, `Цитаты`. Содержательный ответ ссылается на текущие найденные чанки книги и дословные цитаты. При `no_evidence` печатается существующий ответ «Не знаю», `Источники: нет`, `Цитаты: нет`; отказ сохраняется в истории. Ошибка провайдера, поиска, памяти или хранения показывается как ошибка и не маскируется под ответ.

## Память и история

У каждой сессии есть полная история ходов и компактное состояние: `goal` (одна текущая цель), `clarifications` (что пользователь уточнил), `constraints` (действующие ограничения), `terms` (определения). Каждый факт содержит текст и номер реплики пользователя, из которой он получен. Обновления строятся только из новой реплики пользователя, проходят проверку структуры и наличия дословного свидетельства в ней. Новое уточнение дополняет память; явная поправка удаляет или заменяет прежний факт. Ошибка формата обновления допускает одну попытку исправления, после чего ход завершается ошибкой без изменения состояния.

Подготовка хода одним вызовом модели возвращает обновления памяти и самостоятельный поисковый запрос. Она получает текущее состояние и последние четыре пары реплик с ограничением размера. Полная история остаётся в SQLite, но не отправляется модели целиком. Поисковый запрос нужен для разрешения ссылок вроде «а как это проверить?»; сам ответ адресуется текущей реплике и учитывает состояние. Предыдущие ответы служат контекстом диалога, а не доказательством фактов из книги. Для содержательного ответа допустимы только цитаты из чанков, найденных на текущем ходе.

SQLite хранит сессии и завершённые ходы: исходную реплику, результат, поисковый запрос, снимок состояния, источники и цитаты. Ход и обновлённое состояние фиксируются одной транзакцией после успешной обработки. При ошибке старое состояние остаётся доступным, а пользователь может повторить реплику. Сессия имеет номер версии: если другая копия CLI изменила её после чтения, запись устаревшего хода отклоняется без потери данных; пользователь повторяет вопрос в обновлённой сессии.

## RAG и источники

Для каждого нового вопроса выполняется один структурный поиск Top-20, затем reranking с порогом дня 24 и выбор до пяти чанков. И поиск, и reranking используют подготовленный `search_query`; ответ адресуется исходной реплике. `rag_day24.answer_question_day24` расширяется необязательными `search_query` и `conversation_context`; без них поведение дня 24 остаётся прежним. В промпт ответа передаются текущий вопрос, компактный контекст диалога и выбранные фрагменты. Метаданные источников берутся из индекса, цитаты проверяются существующим валидатором. В результате сохраняется поисковый запрос и выбранные чанки без векторов.

Сведения о цели и ограничениях показываются в `/state` с источником-репликой. Это отдельный тип происхождения данных; реплики пользователя нельзя выдавать за источник книги. Чат не использует результаты предыдущих поисков как доказательства нового ответа.

## Проверка

Модульные тесты с подменёнными внешними вызовами проверяют сохранение после перезапуска, изоляцию сессий, обновление и исправление памяти, поисковый вызов на каждом ходе, контекст для вопроса со ссылкой на предыдущую реплику, проверку цитат, явный отказ и отсутствие записи при ошибке. Регрессионные тесты дней 22–24 проходят.

Два заранее записанных сценария содержат по 12 пользовательских реплик о темах книги: уточнение цели, ограничения, термин, вопросы с местоимениями, исправление ограничения и возврат к исходной цели. В одном сценарии CLI перезапускается после шестой реплики. Фактические стенограммы и отчёт сохраняются в `docs/day-25/`. Для каждого хода фиксируются наличие поиска, источников либо явного отказа, действующее состояние задачи и ручная оценка опоры ответа на цитаты. Успех: на всех 24 ходах выполняется поиск; финальная цель и действующие ограничения сохранены; у каждого содержательного ответа есть проверенные источники и цитаты; ошибки и частично подтверждённые ответы отмечаются открыто.
