# День 21 — локальный индекс книги Agentic Design Patterns

## Цель и выбранный корпус

Построить воспроизводимый локальный индекс русскоязычной книги
`agentic-design-patterns-ru.epub` и сравнить фиксированное разбиение текста
с разбиением по структуре глав и подразделов. Результат демонстрируется через
консольные команды сборки, сравнения и поиска.

Исходный файл предоставлен пользователем:
`/Users/d.fedotova/Downloads/agentic-design-patterns-ru.epub`. Проверка архива
успешна. Метаданные EPUB: название `Agentic Design Patterns`, автор Кирилл
Мокевнин, язык `ru`; в разделе прав указаны CC BY-SA 4.0 для текста и диаграмм
и CC0 для примеров кода. В 45 XHTML-файлах около 29 400 слов. Без обложки,
титула, оглавления, вводной страницы и страницы о лицензии остаётся около
29 000 слов в 40 содержательных XHTML-файлах — больше требуемых 20–30 страниц.
Каждый такой файл считается документом набора. В индекс идёт доступный
текст; OCR диаграмм и изображений не входит в задачу.

Для повторяемости сохранить копию EPUB в `docs/day-21/corpus/`, исходный SHA-256,
атрибуцию и условия использования в документации результата. Файлы из прежнего
варианта с README и отчётами проекта в корпус не входят.

## Выбранный подход

Рассмотрены три источника: внутренняя документация проекта, страницы официальной
документации из интернета и предоставленный EPUB. Выбран EPUB: объём уже
достаточен, все главы относятся к одной теме, а заголовки H1–H3 дают явные
структурные границы. Для демонстрации выбран CLI; отдельный веб-экран не нужен.

Эмбеддинги генерирует локальная Ollama с моделью `embeddinggemma`, подходящей
для русскоязычного текста. Приложение вызывает `POST /api/embed` с массивом
текстов и `truncate: false`; модель и локальный сервер должны быть доступны к
моменту сборки. Если их нет, команда сообщает, что нужно запустить или
загрузить, и не оставляет неполный индекс. Лексические TF-IDF-векторы не
подменяют результат задания.

## Извлечение и метаданные

- Читать EPUB как ZIP стандартными средствами Python. Порядок документов брать
  из `META-INF/container.xml`, OPF manifest и spine, а не из алфавитного списка
  файлов архива.
- Из XHTML извлекать заголовки, абзацы, списки и текст блоков кода. Исключать
  служебные страницы, HTML-навигацию и пустые фрагменты. Сохранять разделение
  блоков и порядок текста. HTML-теги и повторяющиеся элементы навигации не
  должны попадать в текст чанка.
- У каждого чанка обязательны `source` (имя EPUB и внутренний XHTML-путь),
  `title` (заголовок главы), `section` (путь H1/H2/H3), `chunk_id`, стратегия,
  текст и порядковый номер. Для фиксированного чанка, пересекающего заголовок,
  `section` указывает начало, а дополнительное поле отмечает пересечение.
- ID стабилен при одинаковых EPUB, настройках и стратегии; SHA-256 исходного
  файла и параметры сборки хранятся рядом с индексом.

## Две стратегии разбиения

Обе стратегии обрабатывают одни и те же 40 содержательных файлов и используют
один ориентир: не более 250 слов на чанк, перекрытие 40 слов для длинных
последовательностей. Это **слова по пробелам**, а не точное число токенов модели.

1. **Фиксированная:** скользящее окно по тексту каждой главы. Окно не выходит
   за границы файла, но может пересечь заголовок подраздела.
2. **Структурная:** начать новую единицу на H1/H2/H3. Если раздел длиннее
   лимита, разбить его тем же окном и перекрытием. Короткий раздел остаётся
   отдельным чанком; он не сливается с соседним разделом.

Текст для модели включает название главы и путь раздела перед содержимым в
обеих стратегиях. Пустые чанки не создаются. Все слова содержательных глав
должны встречаться хотя бы в одном чанке каждой стратегии.

## Индекс, интерфейс и сравнение

- SQLite-файл `docs/day-21/index.sqlite3` хранит сборку, документы и чанки двух
  стратегий. В каждом чанке находятся текст, метаданные и плотный вектор.
  Сохраняются модель, размерность, настройки и хеш EPUB. Для небольшого корпуса
  поиск считает косинусное сходство по сохранённым векторам без FAISS.
- `python3 deepseek-api/document_index.py build` собирает индекс и печатает
  количество глав, чанков и прогресс эмбеддингов. Новая база заменяет прежнюю
  только после успешной полной сборки.
- `compare` печатает таблицу числа чанков, длин, перекрытия и пересечений
  структурных границ; сохраняет фактические показатели и несколько одинаковых
  поисковых запросов в `docs/day-21/comparison.md`.
- `search` принимает запрос и стратегию и печатает лучшие результаты: оценку,
  главу, раздел, `source`, `chunk_id` и короткий фрагмент. Для запроса используется
  та же модель, что записана в индексе.
- Раздел дня 21 в `deepseek-api/README.md` объясняет подготовку Ollama,
  сборку, сравнение и несколько команд для живой демонстрации.

Сравнение фиксирует измерения и наблюдаемые различия; вывод об общем
превосходстве стратегии по нескольким примерам не делается.

## Ошибки и проверки

Сборка выдаёт понятную ошибку при отсутствующем или повреждённом EPUB, пустом
содержательном корпусе, недоступной Ollama, отсутствующей модели, ошибке API,
усечённом ответе, неверном количестве, размерности или значениях векторов.
Частичная база не заменяет существующую. `search` и `compare` проверяют наличие
готовой базы и ожидаемой схемы.

Автоматические тесты проверяют порядок глав, исключение служебных страниц,
извлечение заголовков и кода, оба разбиения, покрытие текста, стабильность ID,
обязательные метаданные, сохранение и повторное открытие SQLite. Ответы Ollama
в модульных тестах подставные; отдельный живой прогон создаёт настоящий индекс
и проверяет консольную демонстрацию и отчёт на реальном EPUB.

## Критерии готовности

1. Локальная база повторно открывается и содержит обе стратегии для одного
   корпуса; каждый чанк имеет текст, вектор и четыре обязательных поля.
2. Корпус превышает минимум 20–30 страниц, а отчёт указывает точный объём
   извлечённого текста и исключённые страницы.
3. `build`, `compare`, `search` работают из консоли и дают проверяемый пример
   различий между стратегиями.
4. README позволяет воспроизвести сборку; источник и права книги указаны.
