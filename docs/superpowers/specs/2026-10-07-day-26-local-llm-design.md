# День 26 — запуск локальной генеративной LLM

## Цель

Показать, что генеративная модель хранится и запускается на этом компьютере, доступна через CLI и локальный HTTP API и отвечает на три запроса разной сложности. Результат эксперимента фиксируется в `docs/day-26/results.md` с фактическими ответами. Приложение дней 1–25, RAG-индекс и облачные провайдеры для этого задания не меняются.

## Что уже есть на 7 октября 2026 года

- Установлена Ollama `0.35.1`; Homebrew показывает сервис `ollama` в состоянии `started`.
- `GET http://127.0.0.1:11434/api/tags` успешно отвечает, а `ollama list` показывает только `embeddinggemma:latest` (621 MB).
- Локальная `embeddinggemma` использовалась для эмбеддингов в дне 21. Её API указывает capability `embedding`; это не генеративная модель для ответов на обычные вопросы. Наличие работающей Ollama поэтому пока не завершает день 26.
- На компьютере Apple M5 Pro с 48 ГБ памяти и достаточно свободного дискового пространства для компактной модели.

## Выбор модели и границы

Использовать существующую Ollama и загрузить `qwen2.5:1.5b` (около 986 MB). Эта модель поддерживает русский язык и даёт короткий, воспроизводимый сценарий без доработки проекта. Альтернатива `qwen2.5:3b` занимает около 1,9 GB и может отвечать точнее, но для минимальных требований задания загрузка более крупной модели не нужна. Повторная установка Ollama, подключение её к Codex или переписывание RAG не входят в задание.

Загрузка модели требует сети один раз. После загрузки запросы отправляются на `127.0.0.1:11434`; в демонстрации используется точное имя модели без облачного суффикса. Если сервис после перезапуска машины не отвечает, запустить его через `brew services start ollama` и повторить проверку. Не запускать второй `ollama serve`, пока сервис Homebrew уже работает.

## Сценарий выполнения

1. Проверить `ollama --version`, `brew services list`, `ollama list` и `curl -fsS http://127.0.0.1:11434/api/tags`. Записать версию, состояние сервиса и список моделей.
2. Выполнить `ollama pull qwen2.5:1.5b`; после завершения убедиться, что модель появилась в `ollama list` и `/api/tags`.
3. Проверить CLI командой `ollama run qwen2.5:1.5b 'Ответь только числом: сколько будет 2 + 2?'`. Вывод должен содержать ответ `4`.
4. Выполнить все три запроса из таблицы ниже через локальный `POST /api/generate` с полями `model`, `prompt` и `stream: false`. Для каждого сохранить фактический текст поля `response`, факт `done: true`, код HTTP и время выполнения. Не подменять ответы ожидаемыми формулировками.
5. Записать команды, три запроса, фактические ответы и проверку критериев в `docs/day-26/results.md`. Если один ответ ошибочен, отметить это как наблюдение и при необходимости повторить запрос; факт запуска модели и качество ответа оценивать отдельно.

Пример формы HTTP-запроса; в каждом из трёх запусков заменяется только `prompt`:

```bash
curl -fsS -w '\nHTTP %{http_code}; total %{time_total}s\n' \
  http://127.0.0.1:11434/api/generate \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen2.5:1.5b","prompt":"Ответь только числом: сколько будет 2 + 2?","stream":false}'
```

| Уровень | Запрос | Что проверять в ответе |
|---|---|---|
| Простой | «Ответь только числом: сколько будет 2 + 2?» | Есть непустой ответ `4`. |
| Средний | «Объясни школьнику в двух предложениях разницу между локальной и облачной LLM.» | Есть понятное различие по месту исполнения и доступу к внешнему сервису. |
| Сложный | «Один исполнитель должен завершить четыре задачи за 90 минут: A — 30 минут; B — 25 минут после A; C — 20 минут после B; D — 15 минут независимо от остальных. Предложи порядок задач, укажи начало и конец каждой, проверь ограничения и общую длительность.» | План учитывает зависимости A → B → C, не накладывает задачи друг на друга и завершается не позже 90-й минуты; сумма длительностей равна 90. |

## Проверка и критерии приёмки

- `ollama list` и `/api/tags` содержат `qwen2.5:1.5b`; запросы идут на `127.0.0.1`, без ключа облачного API.
- CLI возвращает содержательный текст на простой запрос; HTTP API возвращает код 200, `done: true` и непустое `response` на каждый из трёх запросов.
- В `docs/day-26/results.md` сохранены все три **фактических** запроса и ответа, версия Ollama, имя модели, команды проверки и краткая оценка каждого ответа. Локальность подтверждается адресом API, локальным списком моделей и отсутствием облачной модели в запросе.
- Ошибку подключения, загрузки или генерации фиксировать как невыполненный пункт, а не как успешный ответ. Если модель выдаёт неточный ответ, указать это в оценке и сохранить исходный вывод.
