# День 12 — общий профиль пользователя

## Цель

Добавить в локальный чат единый сохраняемый профиль пользователя. Профиль хранит имя, стиль ответа, предпочитаемый формат и ограничения. Активный профиль автоматически влияет на каждый запрос всех агентов, но не заменяет их системные инструкции или данные памяти.

## Решение

Ввести отдельную сущность `UserProfile`, принадлежащую `AgentRegistry`, а не отдельному агенту. Это повторяет разделение Codex: пользовательские предпочтения имеют глобальную область действия, а настройки агента и правила конкретной задачи остаются локальными.

Профиль имеет фиксированную схему:

```json
{
  "name": "Пользователь",
  "style": "ясный и дружелюбный",
  "format": "краткие абзацы",
  "constraints": "без Markdown"
}
```

Все поля — непустые строки с ограниченной длиной. Некорректный профиль отклоняется без изменения сохранённого состояния.

## Поток данных

1. При создании реестра загружается профиль из общего JSON-состояния; для старых сохранений используется профиль по умолчанию.
2. `GET /api/profile` возвращает один активный профиль.
3. `PUT /api/profile` принимает только четыре поля профиля, валидирует их, сохраняет новое общее состояние атомарно и возвращает профиль.
4. Перед каждым вызовом модели `AgentRegistry` передаёт текущий профиль в `Agent.respond`.
5. Агент формирует итоговую системную инструкцию в предсказуемом порядке: собственный `systemPrompt` агента, настройки JSON-формата (если включены), затем маркированный блок «Профиль пользователя», затем существующий контекст памяти. Данные памяти по-прежнему явно помечены как контекст, а не инструкции.
6. В метаданных последнего запроса сохраняются итоговый system prompt и снимок профиля, поэтому его применение можно проверить без вызова внешней модели.

## Интерфейс

В правой панели появляется раздел «Профиль пользователя» перед настройками ответа. Он содержит четыре поля и статус сохранения. Поля работают как существующие настройки агента: изменения сохраняются с короткой задержкой, а отправка сообщения сначала дожидается сохранения профиля. Профиль не меняется при переключении, создании или удалении агента.

## Ошибки и совместимость

- Неверная форма JSON, лишние ключи, пустые или слишком длинные значения дают `400` и не меняют профиль.
- Ошибка записи состояния даёт существующую безопасную ошибку хранилища и откатывает профиль в памяти.
- Состояние версии 7 мигрируется до следующей версии с профилем по умолчанию; агенты, история, метрики и общая долговременная память сохраняются.
- Старые клиенты могут продолжать работать с маршрутами агентов: профиль добавляется отдельными маршрутами.

## Проверка

Тесты должны доказать:

1. Два отличающихся профиля формируют разные итоговые system prompts для одного и того же текста.
2. После обновления профиль автоматически применяется к запросам двух разных агентов.
3. Профиль переживает перезапуск реестра и миграцию старого состояния.
4. Некорректное обновление через API возвращает `400` и не изменяет активный профиль.
5. Страница содержит форму профиля и отправляет `GET`/`PUT` в новый маршрут.

## Вне объёма

Не добавляются несколько профилей, аккаунты, авторизация, профиль на отдельного агента и автоизвлечение предпочтений из сообщений. Для дня 12 достаточно одного явно редактируемого активного профиля.
