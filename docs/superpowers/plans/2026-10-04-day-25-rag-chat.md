# Day 25 RAG Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a persistent CLI chat that retrieves book context for every user turn, keeps the task goal and clarifications, and displays verified sources.

**Architecture:** Store sessions and completed turns in a separate SQLite database with optimistic version checks. One preparation model call returns a bounded memory patch and a contextual search query. The Day 24 RAG path searches and reranks with that query, then answers the original message with current excerpts, recent dialogue and validated citations.

**Tech Stack:** Python 3, `sqlite3`, `unittest`, existing Ollama index, cross-encoder reranker, Z.AI/DeepSeek provider.

**Chosen Day 25 provider:** `deepseek-v4-flash` by default for chat and scenario runner, using `DEEPSEEK_API_KEY` as authorized by the user. Day 24 defaults remain unchanged.

**Design reference:** `docs/superpowers/specs/2026-10-04-day-25-rag-chat-design.md`.

## Task 1: Pure task memory

**Files:** Create `deepseek-api/rag_chat_memory.py`, `deepseek-api/tests/test_rag_chat_memory.py`.

- [ ] Write tests for an empty state, goal/constraint/term/clarification additions, explicit replacement/removal, unchanged fact preservation, duplicate suppression, invalid evidence, invalid operation and size limits. A fact has `{"text": str, "turn": int}` and every newly added fact needs an exact nonempty `evidence` substring from the latest user message.
- [ ] Run `.venv/bin/python -m unittest discover -s deepseek-api/tests -p test_rag_chat_memory.py -v`; confirm the missing module/functions cause failure.
- [ ] Implement `empty_state()`, `validate_preparation(content, current_message, state, turn_number)` and `prepare_payload(message, state, recent_turns, model)`. JSON result shape: `{"search_query": str, "changes": [{"op": str, "text": str, "evidence": str, "term": str?}]}`. Allowed ops: `set_goal`, `add_clarification`, `add_constraint`, `set_term`, `remove_clarification`, `remove_constraint`, `remove_term`; removals name an existing exact text or term. Each change requires evidence from this message. Trim the query and require 1–500 characters; an empty query is a validation failure eligible for the single repair attempt. Limit each text/term/evidence to 300 characters; allow at most 20 clarifications, 20 constraints and 20 terms. Validate and apply the whole patch to a copy or reject it atomically. `set_goal` replaces the goal; duplicates keep the earlier provenance.
- [ ] Add tests for `conversation_context(state, recent_turns)` capped at the last four complete turns and a fixed character budget. Include the state and distinguish user messages from previous assistant answers; previous answers are context, never citations.
- [ ] Run focused tests again; expected all pass. Review `git diff --check`.

## Completion gate

- Every non-command message launches retrieval; both retrieval stages use the prepared query.
- History and task state survive restart, corrections replace old facts, and two sessions stay isolated.
- Every substantive answer has current-turn verified sources/citations; every refusal explicitly shows no sources.
- Both 12-turn scenarios have real transcripts and a per-turn review of goal retention and grounding.
