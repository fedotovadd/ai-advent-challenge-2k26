# День 16 — вкладка MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить в локальный веб-чат вкладку MCP, которая подключается к публичному Streamable HTTP MCP-серверу по кнопке и показывает его инструменты.

**Architecture:** Новый модуль `mcp_client.py` изолирует проверку URL и асинхронную работу MCP SDK. `web.py` даёт браузеру один same-origin маршрут и получает клиент как внедряемую зависимость. Отдельный `mcp-controls.js` строит интерфейс вкладки и отображает ответ, не связывая MCP-инструменты с DeepSeek.

**Tech Stack:** Python 3.10+, MCP Python SDK (`mcp>=1.30,<2`), Streamable HTTP, `unittest`, vanilla JavaScript.

---

## File structure

- `deepseek-api/mcp_client.py` — проверяет публичный URL и возвращает список `{"name", "description"}` через MCP SDK.
- `deepseek-api/web.py` — `POST /api/mcp/tools`, обработка ошибок и dependency injection в `ChatServer`.
- `deepseek-api/main.py` — передаёт стандартный MCP-клиент при обычном запуске приложения.
- `deepseek-api/static/mcp-controls.js` — содержимое вкладки и запрос к локальному API.
- `deepseek-api/static/index.html` — переключатель «MCP», контейнер вкладки, загрузка скрипта и responsive-стили.
- `deepseek-api/tests/test_mcp_client.py` — unit-тесты URL и преобразования моделей MCP.
- `deepseek-api/tests/test_web.py` — тесты маршрута, origin и ответа.
- `deepseek-api/tests/test_mcp_ui.py` — статические проверки контракта вкладки.
- `deepseek-api/requirements.txt` и `deepseek-api/README.md` — зависимость и инструкция запуска/проверки Дня 16.

- [ ] **Step 2: Запустить тест, чтобы подтвердить падение.**

Run: `python3 -m unittest tests.test_mcp_client -v`

Expected: FAIL, because `mcp_client` does not exist.

- [ ] **Step 3: Добавить MCP SDK и минимальный адаптер.**

В `requirements.txt` добавить совместимую 1.x версию SDK: `mcp>=1.30,<2`. В `mcp_client.py` создать:

```python
def normalize_server_url(value): ...

async def list_public_tools(url, *, transport_factory=streamable_http_client): ...

def list_tools(url):
    return asyncio.run(list_public_tools(url))
```

`list_public_tools` создаёт `httpx.AsyncClient(timeout=10.0, follow_redirects=False)` и передаёт его как `http_client` в `streamable_http_client`; тест переданного клиента фиксирует оба значения. Затем код использует `ClientSession`, `await session.initialize()` и `await session.list_tools()`. Он не вызывает инструменты. Валидатор отклоняет host, который является или резолвится в непубличный IP. SDK может обработать только 307/308-редирект внутри исходной схемы, хоста и порта; тест транспорта подтверждает отказ при попытке сменить origin.

Run: `python3 -m unittest tests.test_mcp_client -v`

Expected: PASS.
