## Живая демонстрация

В отдельном тестовом чате на 127.0.0.1:8019 отправлена команда:

```text
/research mcp language:python
```

Чат вызывал настоящий MCP-сервер на 127.0.0.1:8003/mcp, сервер обращался к
публичному GitHub API. Пользовательская история основного чата не использовалась:
демонстрация работала с отдельным `/tmp/day19-demo-agents.json`.

Наблюдения в браузере:

1. Сразу после отправки виден выполняющийся search, остальные шаги ожидают.
2. После получения GitHub-ответа видны три успешных шага; search вернул 3 элемента.
3. Раскрытие summarize показывает фактический search_result и полный MCP-ответ.
4. После обновления страницы карточка, три успешных шага и путь к файлу восстановились.
5. После остановки тестового MCP-сервера `/research demo-error` показал ошибку
   search с подсказкой запуска; summarize и saveToFile остались «Не выполнялся».

Для проверки использован встроенный браузер через доступный адаптер управления:
основной browser-use модуль не загрузился из-за отсутствующей native-сборки classic-level.

## Ограничения

- summarize — детерминированный обзор метаданных, без анализа кода и LLM.
- Карточки подчиняются стратегии хранения истории; отчёты автоматически не удаляются.
- При транспортном тайм-ауте saveToFile файл уже может существовать. Повторов нет.
- Два новых исследования не держат общий registry lock во время MCP-запросов.
  Обычный LLM-чат наследует прежнюю общую блокировку и может задержать обновления
  другого агента. Изменение всей архитектуры обычного чата не входило в реализацию.
- Тестовый чат использует подставной ответ для обычных сообщений; `/research`
  использует настоящий MCP/GitHub и не зависит от этой подстановки.
